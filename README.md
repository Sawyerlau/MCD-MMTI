# 麦麦人格 MMTI

> McDonald's Mood & Taste Index
> **全网都在告诉你该怎么吃，MMTI 告诉你此刻你是谁。**

一个基于麦当劳 MCP Server 的创意 Skill。它不做「买什么最省」的决策，而是读取你的真实订单、优惠券时间轴、积分账本与活动日历，判定你此刻的麦当劳人格，并生成一张可分享的人格卡。

## 核心机制：券时段轮转

MMTI 的人格不是贴在用户身上的静态标签，而是由**真实的券有效期**、活动日历与当前时段共同生成。

用户的优惠券带有精确到「周几 + 时段 + 到店/外送」的有效期。例如一张 ¥9.9 早餐券的有效期为「周一至周五 05:00-10:29 到店专用」——这意味着：

> 周一早上 7 点的用户，在物理上不可能被判定为「深夜被鼓励」。

这是一条硬约束。人格判定引擎会在四个时点自动轮转：

```text
今日人格轨迹
06:30  满分解      早餐券自动生效，¥9.9 两件套
12:30  券时钟      午间时段可用券待使用
18:30  券时钟      当日到期券提醒
22:30  深夜被鼓励  热朱古力 125 kcal

今日合计：节能 12.4 元 / 摄入 1840 kcal
```

## 16 型人格坐标系

人格分属四大族群，每族四人。族群是坐标系而非标签——用户知道自己落在哪个象限，比知道自己叫什么更重要。

## 安装

### 1. 配置 MCP Server

在 `~/.workbuddy/mcp.json` 中加入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

配置后需在连接器管理页面右上角的「自定义连接器」入口对新服务点击「信任」才会加载。

### 2. 安装 Skill

将 `SKILL.md` 放入技能目录，或直接在 WorkBuddy 中引用该文件。

---

### 场景二：今天吃什么（下单前）

**用户说**：
```
今天吃什么？
```

**MMTI 会做**：

1. `now-time-info` 确认当前时段
2. `query-my-coupons` 找出此刻可用的券
3. `query-nearby-stores` 定位门店
4. `query-meals` 取实时在售餐品
5. `calculate-price` 计算到手价（注意单位为分，需除以 100）

输出会同时给出：人格 + 推荐餐品 + 用哪张券 + 到手价 + 热量参考。

---

### 场景三：换人格

**用户说**：
```
我是卷王 / 换成零糖战士
```

**MMTI 会做**：从 16 张预设中切换，推荐逻辑同步改变，人格卡重新生成。

系统推荐仅供参考，用户的选择**优先级最高**。切换后仍受真实数据约束——比如「零糖战士」只会推荐营养库中确实存在的 0 kcal 饮品，不会凭空编造。

---

### 场景四：看看今天的人格轨迹

**用户说**：
```
我今天会是哪些人格？
```

**MMTI 会做**：对一天中四个时点分别判定，展示轮转轨迹。

```text
今日人格轨迹
------------------------------
  06:30  满分解
  12:30  券时钟
  18:30  券时钟
  22:30  深夜被鼓励
```

同一个人一天可以过 4 个人格。**人格描述的是"你此刻是谁"，不是"你是谁"。**

---

### 场景五：数据不足时

**用户说**（首次使用，订单为空）：
```
我是谁？
```

**MMTI 会做**：直接告知数据不足，不编造结论。

```text
判定依据：还没有足够的订单数据，口味人格需要 2 笔以上订单才能判定。
你可以直接从 16 张人格里选一张，我按那张推荐。
```

这是刻意的设计——**口味人格需要至少 2 笔订单才可靠**，用1 笔数据下结论是不诚实的。

## 数据关联规则

`order-list` 与 `list-nutrition-foods` 是两个独立接口，MMTI 在本地关联它们。**这一步有三个坑，都已在代码中处理**：

### 坑一：套餐名不在营养库里

订单主品常是「精选超值随心配」这类套餐名，营养库没有对应条目。**正确做法是按子项累加**，而不是取第一个匹配项。

否则会把 147 kcal 的饮料当成整单热量——实测曾因此把 3 笔 13.9 元的套餐误判为「燕麦轻盈派」。

### 坑二：子项匹配不全不能用

子项「高达吉士双牛堡」若不在营养库，只匹配到 0 卡可乐，直接累加会把一单算成 **0 kcal**。

MMTI 的规则：**子项匹配覆盖率不足 60% 时视为匹配失败**，结果仅作品类参考，不参与热量统计。

### 坑三：名称需要模糊匹配

MCP 返回的餐品名带营销修饰（「可乐麦炫酷」「那么大鸡排（椒盐风味）」），营养库用标准品名。匹配采用三级策略：

```
1. 精确匹配          「无糖可口可乐中杯」→ 命中同名词条
2. 归一化后精确匹配   去括号、去营销词后精确匹配
3. 子串包含（取最长） 「那么大鸡排（椒盐风味）」→「那么大鸡排」
```

**杯型（大杯/中杯/小杯）必须保留**，否则 0 kcal 的中杯会被 53 kcal 的大杯抢占。

### 修复前后对比（真实 MCP 数据）

| | 修复前 | 修复后 |
| --- | --- | --- |
| 营养关联成功率 | 0/3 | 3/3 |
| 平均热量 | 105 kcal（错误） | 551 kcal |
| 判定人格 | 燕麦轻盈派 | 卷王 |

### 冷启动保护

口味人格需要**至少 2 笔已匹配订单**才可靠。订单不足时 MMTI 会直接告知数据不足并引导用户自选，不用1 笔数据编造结论。

## 对话人格

MMTI 的对话人格定义在 `SOUL.md`，角色是**麦麦人格官**——一个把麦当劳数据翻译成人话的角色。

性格底色是「有点损但靠谱」。损是因为会拿用户的订单开玩笑，靠谱是因为报的每个数字都来自 MCP 真实返回。

核心原则：

| 原则 | 要求 |
| --- | --- |
| 说人话 | 一句话说完，不解释算法过程 |
| 报真数 | 每个数字都来自 MCP 实时返回，没数据就说「数据不可用」 |
| 调侃数据 | 可以拿订单开玩笑，绝不调侃用户本人 |
| 保持克制 | 一条回复最多一句玩笑，其余说正事 |
| 不当医生 | 热量数据一律标「信息参考」，不提供健康建议 |

对比示例：

```
❌ "根据您的订单数据，系统为您判定的人格是券时钟"
✅ "券时钟。你有 2 张券现在就能用，麦旋风任选 9.9 元，23:59 前用掉最划算。"
```

16 张人格各有说话示例，用户自选人格时**不做劝阻**——用户比你清楚自己想吃什么。

## 人格卡版式

三段式结构，第二段是**可信度锚点**：

```text
┌─────────────────────────────────┐
│  MMTI · 系统判定，可推翻         │  ← 第一段：身份来源
│                                 │
│        随 性 真 香 派             │  ← 人格名 + 族群
│                                 │
│  3 笔订单全是随心配               │  ← 第二段：真实数据
│  跨 3 城 3 店                     │
│  均单价 15.6 元                   │
│  14 张券待规划                    │
│                                 │
│  闭眼点，13.9 真香                │  ← 第三段：人设
│  可切换或自选 16 张人格           │
└─────────────────────────────────┘
```

第二段全部来自 MCP 返回的真实数据，不足则显示「暂无数据」而非省略。这是人格卡能被转发的前提——它不编故事。

## 目标用户

| 群体 | 痛点 | MMTI 的回应 |
| --- | --- | --- |
| 优惠券持有者 | 券分散在各页面，不知何时何地使用 | 自动折叠为「今天该几点去、用哪张」 |
| 减脂期人群 | 想控制热量但不了解麦当劳餐品成分 | 160 款营养数据支撑的人格化推荐 |
| 价格敏感人群 | 积分过期未察觉 | 积分账本 + 抽奖机会实时提醒 |
| 麦麦重度用户 | 口味稳定但缺乏新选择 | 复购画像 + 新品匹配 |

## 项目边界

- **不提供自定义人格**：16 张预设人格为封闭集合，人格切换由用户在预设中选择
- **不构成医疗或营养诊断**：所有热量、钠含量均为「信息参考」，不提供健康建议
- **不代替下单**：MMTI 定位为决策辅助，实际下单由用户跳转官方渠道完成
- **不覆盖积分商城**：`mall-*` 系列为独立链路，不纳入人格判定
